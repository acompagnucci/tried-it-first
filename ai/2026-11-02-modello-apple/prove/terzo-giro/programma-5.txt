=== Risposta ===
Il bug risiede nel confronto tra `BigDecimal` e `double`. Il metodo `equals` di `BigDecimal` non considera il caso in cui i due numeri hanno valori identici ma rappresentazioni diverse a causa della precisione decimale. Ad esempio, `120.0` e `120` vengono considerati diversi.

La correzione più piccola possibile è usare il metodo `compareTo` per confrontare i valori con un piccolo margine di errore:

```java
public class ControlloPagamenti {

    // ... (resto del codice)

    static List<String> fattureNonSaldate(List<Fattura> fatture, List<Pagamento> pagamenti) {
        Map<String, BigDecimal> totalePagato = new HashMap<>();
        for (Pagamento p : pagamenti) {
            totalePagato.merge(p.numeroFattura(), p.importo(), BigDecimal::add);
        }

        List<String> nonSaldate = new ArrayList<>();
        for (Fattura f : fatture) {
            BigDecimal pagato = totalePagato.getOrDefault(f.numero(), BigDecimal.ZERO);
            if (!pagato.compareTo(f.importo()) == 0) {
                nonSaldate.add(f.numero());
            }
        }
        return nonSaldate;
    }

    // ... (resto del codice)
}
```
